RAID OPERATIONS 01

일정 공지는 날짜보다
판단 기준이 먼저입니다

참여자가 “갈 수 있는가”와 “가도 되는가”를 한 번에 판단하려면 날짜만으로는 부족합니다. 목표, 난이도, 예상 종료, 신청 방식과 변경 규칙이 같은 화면에 있어야 합니다.

1. 모집 전에 확정할 여섯 가지

  1. 목표: 올킬, 진도, 특정 보스 트라이처럼 성공 기준을 한 문장으로 씁니다.
  2. 시간: 시작과 종료 시각, 중간 휴식, 연장 가능성을 분리합니다.
  3. 대상: 길드·정공·연합·글로벌 중 누가 신청할 수 있는지 정합니다.
  4. 요건: 아이템 레벨은 참고 기준인지 필수 조건인지 밝힙니다.
  5. 정원: 탱커·힐러·딜러 수와 유동 가능한 자리를 구분합니다.
  6. 결정 방식: 자동 확정인지 운영진 검토 후 수락인지 명시합니다.

2. 신청 마감과 변경 규칙

마감은 단순히 신청 버튼을 닫는 시각이 아닙니다. 운영진이 조합을 확정하고 대기 인원에게 결과를 알릴 시간을 포함해야 합니다. 캐릭터나 전문화 변경은 새 신청으로 중복 생성하지 말고 기존 참여 기록의 변경 요청으로 남기는 편이 안전합니다. 취소는 참여자 본인이 할 수 있어야 하지만, 사유와 시각은 운영 기록에 남겨야 대체 인원을 공정하게 찾을 수 있습니다.

권장 공지 구조

목표 → 일시 → 신청 대상 → 정원 → 요구 조건 → 확정 방식 → 마감 → 취소·변경 규칙 순으로 작성하면 모바일에서도 중요한 정보가 먼저 보입니다.

3. 반복 일정은 ‘복사’가 아니라 규칙으로

매주 같은 요일에 열린다고 해도 공휴일, 시즌 종료, 인원 부족으로 예외가 생깁니다. 반복 규칙과 개별 회차를 분리하면 특정 날짜만 건너뛰어도 나머지 일정이 흔들리지 않습니다. 이미 신청이 있는 회차를 수정할 때는 시작 시각·난이도·신청 방식처럼 참여 판단을 바꾸는 항목을 명확한 중요 변경으로 알리는 것이 좋습니다.

4. 게시 후 운영 점검

  • 공개 URL을 로그아웃 상태에서 열어 일정과 명단 범위가 의도대로 보이는지 확인합니다.
  • 정원이 찬 역할은 신청 불가 또는 대기 처리 상태가 분명한지 확인합니다.
  • Discord 게시물과 웹 일정이 같은 회차를 가리키는지 확인합니다.
  • 일부 캐릭터 정보 갱신 실패가 전체 명단 갱신을 중단시키지 않는지 확인합니다.
