RAID OPERATIONS 03

포럼을 늘리기 전에
게시 규칙을 나누세요

일정 종류마다 새 채널을 만들면 Discord 구조가 빠르게 복잡해집니다. 기존 포럼을 선택하고 ‘누가 연 일정인가’와 ‘어떤 분류인가’를 독립 조건으로 관리하는 편이 확장성이 좋습니다.

게시 전 확인 순서

  1. 조직 설정의 Discord 연결에서 대상 서버와 운영 권한을 확인합니다.
  2. 현재 포럼 목록을 새로고침하고 실제 사용할 기존 포럼을 선택합니다.
  3. 길드·정공 등 게시 범위와 일반·고정 등 일정 분류를 구분해 선택합니다.
  4. 공개해도 되는 일정 한 건으로 게시 위치와 링크를 확인합니다. 민감한 테스트 명단을 공개하지 마세요.
  5. 웹과 Discord에서 같은 날짜·시각·일정 제목이 보이는지 확인합니다.

가상 설정 예시

길드의 고정 일정만 받을 포럼을 정했다고 가정합니다. 해당 길드 범위와 고정 분류를 선택한 뒤, 일반 일정까지 게시되는지 확인합니다. 의도하지 않은 일정이 들어오면 포럼을 새로 만들기 전에 선택한 범위·분류를 다시 확인하세요.

게시되지 않거나 두 번 보인다면

  • 게시 안 됨: 서버 연결, 대상 포럼 존재 여부, 봇의 채널 접근·게시 권한을 서버 관리자와 확인합니다.
  • 중복 게시: 같은 일정을 여러 포럼 연결이 대상으로 삼는지 확인합니다. 반복 게시 버튼을 누르기 전에 기존 글의 일정 링크를 비교합니다.
  • 제목이 다름: 포럼 이름을 바꿨다면 목록을 새로고침합니다.
  • 일부만 실패: 정상 게시된 곳까지 삭제하지 말고 실패한 서버·포럼·일정만 기록해 문의합니다.

제보에는 일정 URL과 대상 포럼, 확인 시각, 보이는 오류를 적고 봇 토큰이나 계정 인증코드는 보내지 않습니다.
