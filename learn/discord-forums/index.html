RAID OPERATIONS 03

포럼을 늘리기 전에
게시 규칙을 나누세요

일정 종류마다 새 채널을 만들면 Discord 구조가 빠르게 복잡해집니다. 기존 포럼을 선택하고 ‘누가 연 일정인가’와 ‘어떤 분류인가’를 독립 조건으로 관리하는 편이 확장성이 좋습니다.

범위와 분류는 다른 축입니다

범위는 길드, 정규 공격대, 길드연합, 공개 글로벌처럼 일정의 소속을 뜻합니다. 분류는 일반, 고정, 트라이 등 운영 목적을 뜻합니다. 예를 들어 하나의 포럼은 특정 길드와 그 길드가 속한 연합 일정을 함께 받을 수 있고, 다른 포럼은 고정 일정만 받을 수 있습니다. 두 조건을 모두 만족할 때만 게시하면 불필요한 복제를 줄일 수 있습니다.

기존 포럼을 우선 재사용하기

  1. Discord 서버 연결 권한을 가진 운영자가 서버를 연결합니다.
  2. 와니온의 조직 Discord 탭에서 현재 포럼 목록을 새로고침합니다.
  3. 기존 포럼을 선택한 뒤 게시 범위와 일정 분류를 복수 선택합니다.
  4. 테스트 일정 하나로 정확히 한 대상 포럼에 게시되는지 확인합니다.
  5. Discord에서 포럼 이름을 바꿨다면 동기화해 표시 이름만 갱신합니다.

중복 생성 방지

동일한 일정과 포럼 조합에는 안정적인 전달 ID를 사용해야 합니다. 같은 Firestore 이벤트나 Discord interaction이 재시도되어도 이미 예약되거나 생성된 전달을 재사용하고, 기존 게시물이 삭제된 경우에만 새 게시물을 만들어 추적 ID를 교체합니다.

수정과 장애 처리

게시 범위 변경은 기존 연결을 삭제하고 다시 만드는 방식보다 연결 문서의 조건을 수정하는 방식이 안전합니다. 권한 부족, 포럼 삭제, 서버 연결 해제는 재시도 가능한 네트워크 실패와 구분해 운영자에게 구체적인 복구 행동을 보여줘야 합니다. 하나의 포럼 게시 실패가 다른 대상 포럼의 정상 게시까지 되돌리게 해서는 안 됩니다.

최종 점검표

  • 선택한 포럼과 범위가 화면에서 명확한 활성 상태로 보이는가?
  • 고정 일정과 일반 일정이 지정한 포럼으로만 가는가?
  • 같은 이벤트를 두 번 처리해도 게시물이 하나인가?
  • 포럼 이름 변경 후 와니온 표시 이름이 갱신되는가?
  • 조직 운영 권한이 없는 사용자가 연결을 바꿀 수 없는가?
